### Added
- **Consensus engine (E6).** The engine builds one recommendation per target, capability and finding kind from the signals of every source instead of keeping the highest-priority source (`dedup.arbitrate()` is gone). Policies `safest` (default, the least aggressive value), `median`, `weighted` (alias `trust-weighted`: upper median weighted by each source's measured realization rate, I3) and `priority` (alias `source-priority`, the former behavior), set by `RECOMMENDATION_CONSENSUS_POLICY` (`config.recommendations.consensusPolicy`). Each recommendation stores a `consensus` block (chosen value and sources, `agreement` = 1 − (max − min)/max, `contested`, reasons, per-source `spread`, independent votes and every vote with its signal id), also shown in the evidence. Sources sharing an engine vote once: Goldilocks and VPA on the same VPA object are one vote (`engine_family`). Agreement ≥ 0.8 between independent sources raises the confidence by 10%; a contested consensus adds the eligibility warning `consensus_contested` and is never approved automatically. A consolidated value restated on another source's recommendation is projected again with the Impact Model, never copied. Example: VPA 300m, KRR 250m, GreenKube 280m → 300m, agreement 0.83.
- **Third-party and pushed signals become recommendations through consensus only**, under their own source id (`source` can now be `krr`, `kubecost`, `push:<client>`...).
- **Recommendation v2 (E4 remainder).** `recommendation_history` gains `target`, `proposal`, `consensus`, `revision` and `fingerprint_v4` (migration `0068`; `impact` already existed). `fingerprint_v4` = SHA-256 of the cluster, the target key, the capability and the finding kind. Rows written before are backfilled losslessly from their flat columns by the next scan (readers derive the same values meanwhile). `GET /api/v2/recommendations` and `GET /api/v2/recommendations/{id}` return the v2 shape (target, typed proposal, consensus, signals, impact, risk, value, eligibility, lifecycle, revisions); v1 keeps its flat fields, the same proposal in flat form (round-trip tested v1 → v2 → v1).
- **Identity and revisions (E7).** `revision` increases when the consolidated proposal changes and the replaced proposal is kept in `recommendation_revisions` (migration `0069`). A recommendation never changes under an open plan (`plan_ready`, `pr_open`, `merged`, `sync_pending`): newer advice is queued as the next revision and promoted once the plan is closed. Plans pin `(recommendation_id, revision)` (`recommendation_plan_pins`), and the PR status comment shows "Newer advice available" (`greenkube.core.recommendation_revisions.newer_revision_for_plan`, wired into the J5 `NewerAdviceHook`).

### Changed
- With the default `safest` policy, a recommendation where VPA proposes less than GreenKube now keeps GreenKube's (higher) value with both sources listed in `sources`; set `RECOMMENDATION_CONSENSUS_POLICY=priority` to keep the former "VPA wins" arbitration.
- Last known advice (E8 check): while a source that supported an active recommendation is incomplete, its last known vote still counts in the consensus (`consensus.last_known`), whatever its priority, so the advice does not flap; the remaining sources' new proposal is written whenever it is not more aggressive than what the last known votes support (a higher request or an increase always goes through). A recommendation still becomes `stale` only when every supporting source completed without re-emitting it (BUG-22).
- A consolidated request recommendation whose value equals the current request (a source reporting "keep the current value" under `safest`, or a minimum floor landing on the current request) is no longer emitted.
- A recommendation frozen under an open plan still has its `expires_at` refreshed by each scan that sees its target, so it no longer expires while its plan or pull request is open; the revising write is conditional on no plan being open. At most 20 superseded revisions are kept per recommendation (plus pinned ones), and the v2 backfill runs once per repository instead of on every scan.
