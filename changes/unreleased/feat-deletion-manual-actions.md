### Added

- **Deletion pull requests for orphaned resources (H6).** The new `delete_resource` action kind turns `ORPHANED_LOAD_BALANCER` and `ORPHANED_PERSISTENT_VOLUME` recommendations into a pull request that removes the resource from Git: the whole file, one document of a multi-document file or one item of a `kind: List` (raw), or the file and its Kustomize `resources:` entry, or one document (Kustomize). Helm sources are refused (a chart-rendered resource needs a values toggle). The rendered result must differ by exactly the deleted resource. Planning re-checks the manifest in Git (opted-out resources, non-`LoadBalancer` Services and infrastructure namespaces are refused) and the plan worker reads the live object before any Git write (`no_effective_change` when it is already gone). Plans carry `deletion_prune_disabled` when Argo CD `syncPolicy.automated.prune` or Flux `spec.prune` is off and `persistent_volume_retained` for a `Retain` volume. Deletions are high risk (volumes) or medium (LoadBalancers), never auto-approved (`deletion_requires_review` in `auto_approve_blockers`, eligibility warning `deletion_reviewed_in_pr`) and have no automated rollback. Zombie workloads and idle namespaces stay manual. The wave-3a deletion evidence model is unchanged.
- **Deletion apply detection and measurement (H6, H0c).** A deletion is applied once its plan synced and the resource is absent from the cluster (`K8sResourceReader`: only a `404` means absent); a resource deleted by hand with no plan in flight is detected too. `ResourceDeletionStrategy` (`verify/deletion.py`, registered for `delete_resource`) measures the released rate: the resource's trusted cost before the change, otherwise the allocated rate frozen with the recommendation; `not_realized` while the resource is still observed.
- **Resource bindings in discovery and planning (H0d).** Each GitOps discovery refresh builds the `ResourceBindingIndex` from the Argo CD and Flux inventories, binds the resources of the kinds registered action kinds target to the managing controller's resolved Git location, records whether that controller prunes, and persists them in the new `resource_bindings` table (migration `0087`, SQLite and PostgreSQL). Plans of resource-bound kinds resolve their source there (unmanaged, ambiguous, unresolved and stale bindings fail closed with an explanation), and the plan worker refuses a binding that changed after approval. Eligibility reports `resource_binding_missing` and `resource_binding_unavailable`.
- **Action framework hooks for non-workload targets (H0c).** `ActionKindSpec` gains `binding_scope`, `resource_kinds`, `auto_approvable`, `matches_recommendation`, `may_express`, `capture_baseline(live, target)`, `is_resource_applied(live, target)` and `planning_warnings`; `primitives` gains `primitive_applied` and `invert_primitives` (generic apply detection and inverse of `SetField`, `RemoveField`, `CreateResource` and `DeleteResource`) and `strategic_merge_patch`. Scans now attach actions to any recommendation a registered kind may express.
- **Manual mode (H9).** `GET /api/v1/recommendations/{id}/manual` returns the `kubectl patch` (built from the kind's primitives), `kubectl delete` or advisory steps of a recommendation with a dry run, the patch, a diff and notes; `POST /api/v1/recommendations/{id}/manual/applied` ("Mark as applied") records an active recommendation as applied by hand with a change id, so it is measured like a merged pull request. The recommendation detail page has an **Apply manually** panel (steps on demand, copy buttons, confirmation) and each active card links to it.

### Changed

- Orphaned LoadBalancer and PersistentVolume recommendations are no longer blocked with `deletion_requires_review`: they report `action_kind: delete_resource` and can open a reviewed pull request when their resource binding is resolved and the automation policy allows their risk.
- A deletion change is recorded against the deleted resource (`Service`/`PersistentVolume`) with `action_kind: delete_resource` instead of a `Pod` target and the container-resources strategy.
- The PR content names a cluster-scoped deleted resource without a leading `/`.
- The automation policy evaluator skips the workload-only gates (rollout state, HPA/VPA/PDB interactions, usage sample coverage) for action kinds bound by resource bindings; controller health, risk, confidence, freeze windows and plan history still apply.
