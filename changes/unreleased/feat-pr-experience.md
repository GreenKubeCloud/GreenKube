### Added
- **PR template v2 (J1).** Plan pull requests get a readable title (`greenkube: rightsize payments/api (cpu 500m→200m, mem 1Gi→512Mi) · −$412/yr · −18 kgCO₂e/yr`, at most 72 characters, details dropped before the title is cut) and a body with Summary (projected totals per month and per year, cost and CO₂e, with the realization factor), Changes (only the resources that change, current → proposed with the delta), Why (consensus and evidence), Risk & what to watch, Assumptions (unit prices, cost source, carbon intensity, PUE, Impact Model version), Rollback, Verification plan, collapsible diffs and a machine-readable `<!-- greenkube:v1 {...} -->` footer. Bodies stay under 60,000 characters; truncation drops diffs first and always keeps sections 1–7 and the footer. Rendering moved out of `plan_worker.py` into the new `greenkube.automation.pr_content` package, with snapshot tests per action kind.
- **Overridable PR template (J1).** `automation.pr.template` (`GITOPS_PR_TEMPLATE`): logic-free Markdown with Jinja2-style `{{ section }}` placeholders, validated at startup (unknown placeholders and unterminated `{{` fail); the footer is always appended. `automation.pr.titlePrefix` (`GITOPS_PR_TITLE_PREFIX`) sets the title prefix.
- **Deep links (J1).** `config.externalUrl` (`GREENKUBE_EXTERNAL_URL`): PRs, commit statuses and status comments link to `/recommendations/{id}`, `/changes/{plan_id}` and `/ledger?change=…`.
- **Commit trailers in the GitOps repository (J1).** The commit GreenKube creates in the target repository uses the PR title as subject and carries `GreenKube-Plan:` and `GreenKube-Recommendations:` trailers (plus `GreenKube-Rollback-Of:` for rollbacks).
- **Derived labels and drafts (J2).** `greenkube`, `optimization/<capability>`, `risk/<level>` and `reliability` (for increases) labels (`automation.pr.defaultLabels`); high-risk plans open as drafts (`automation.pr.draftHighRisk`: GitHub draft, GitLab `Draft:`, Gitea `WIP:` title), and a refused draft falls back to a ready PR.
- **CODEOWNERS routing (J3).** GreenKube parses `CODEOWNERS` (GitHub, GitLab with sections and default owners, Gitea) at the plan's base revision and requests reviews from the owners of the touched paths, in addition to the configured reviewers (`automation.pr.codeowners`).
- **Lifecycle feedback on the PR (J5).** A `greenkube/validation` commit status (render diff valid, policy result) on the PR head (`automation.pr.commitStatus`), and one GreenKube status comment per merged PR, edited in place, never duplicated, with the merged, synced (revision, controller), applied, measuring (ETA) and outcome (measured savings with CI, not realized, inconclusive, contaminated, rollback review) steps and a ledger link (`automation.pr.lifecycleComments`, `automation.pr.lifecycleLookbackDays`). The sync step is posted as soon as it is observed; the leader controller refreshes the others every 5 minutes from change measurement (or the interim verifier when it is off). A "newer advice available" hook is ready for recommendation revisions (E7).
- Git providers: commit statuses, PR comment create/list/edit, label and reviewer additions on an open PR, and CODEOWNERS reads for GitHub, GitLab and Gitea.

### Changed
- **Labels no longer have to exist beforehand (J2).** Gitea now creates missing configured labels instead of failing the operation; GitHub and GitLab already created them implicitly. The docs drop the "labels must pre-exist" requirement.
