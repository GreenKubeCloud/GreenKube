### Added

- **Recommendation detail page (K3):** `/recommendations/{id}`, the target of pull-request links (J1), shows the proposal and expected value, the server-side delivery eligibility with each blocker's code, message and fix and the evidence warm-up ETA, the Impact Model projection by cost and CO₂e component with its assumptions, the review evidence (window, samples, coverage, p50/p95/p99/max, restarts, OOM kills, rollback conditions, diff), pull requests with their sync state, measured savings apart from the projection, and the grouped lifecycle timeline. A **Sources and consensus** section (policy, chosen value, supporting sources, per-source proposals, counted votes, contested reasons) appears only when the recommendation carries a Recommendation v2 consensus. Each recommendation card links to its detail page.
- **Change and ledger pages (J1 deep links):** `/changes/{plan_id}` shows the plan, its pull request, the applied change and its latest measurement (a plan removed by retention still shows its change); `/ledger` shows the savings totals per method and the applied changes with a state filter and cursor paging, and `?change={change_id or plan_id}` opens one change with its measurement, 90% interval, original projection and per-recommendation split. Pull-request links no longer land on a missing page.
- **Setup checklist and banner (K6, F1 UI):** `/setup` renders `GET /api/v1/setup/status`: capability states and checks grouped by category, each with a status word, reason, fix text, copyable snippet, in-app action and documentation link (only `https://` or in-app). A dismissible banner on every page counts the checks that need attention until the setup is complete; a server without the endpoint shows no banner.
- **Repository suggestions (F2 UI):** the setup page lists the repositories found by discovery and lets an administrator **Allow these N repositories**; a Helm values snippet returned by the server is shown to copy.
- **Sources page (K6):** `/sources` lists every recommendation source (problem sources first) with status and reason, last run, counts, measured track record and registry problems, and loads a source's recent runs with their diagnostics on demand.
- New `docs/ui.md` describes the pages, the deep links and the never-summed savings.

### Changed

- **Savings-first Overview (K1):** the home page is now **Overview**. It leads with realized savings from the ledger (with the measured run rate), savings pending verification and the projected opportunity of open recommendations with its risk-adjusted expected value, each labeled `Measured` or `Projected` and never added together; reliability recommendations are counted apart. Changes in flight (open pull requests, applied, measuring), the top 5 recommendations in server expected-value order with their delivery state and links to their detail pages, and empty and evidence warm-up states follow; the footprint KPIs and charts move below. The navigation gains **Ledger**, **Sources** and **Setup**, and marks the current page with `aria-current`.
