### Fixed
- Argo CD multi-source apps that combine a Helm chart, a `ref: values` source and a `path` source of plain manifests (HTTPRoutes, ConfigMaps) no longer leave their workloads `ambiguous` (F-02). A workload carrying Helm ownership metadata (`app.kubernetes.io/managed-by: Helm`, `heritage: Helm`, `helm.sh/chart`, or a `meta.helm.sh/release-name` equal to the chart's release) binds to the chart and its values source, when the other candidate is a plain directory source. The evidence is recorded in the candidate's `owner_selection`, with the competing manifests directories; the Helm values planner then fails closed when one of them declares a resource of the workload's kind and name, or lies outside the repository snapshot so it cannot be checked. A Kustomize or plugin `path` source, two Helm sources, or a release annotation naming another release still fail closed.
- The `greenkube.cloud/helm-values-mapping` annotation's `source_index` now selects the owner of a multi-source Application (the chart source, or the chart whose `$ref` values source it names) instead of being overridden by the ambiguity.
- Rewritten Helm values files and Flux HelmRelease manifests are no longer folded at 80 columns (F-05).
- One Git repository spelled two ways (`.../repo.git` and `.../repo`, a trailing `/`, `git@host:org/repo.git`, `ssh://git@host[:port]/org/repo.git`, `https://host/org/repo.git`) is now recognized as one repository: a monorepo chart is no longer blocked as `cross-repository-git-chart`, its `$values` files plan, and the repository suggestions no longer drop it as a chart-only repository. Repository identity for comparison is the host plus the path without `.git` or a trailing `/` (`repository_identity`, `same_repository`); the persisted form is unchanged.
