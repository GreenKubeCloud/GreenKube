### Added
- **Local cluster aliases (delivery safety).** `automation.localClusterAliases` (`GITOPS_LOCAL_CLUSTER_ALIASES`, JSON list) names the extra Argo CD destination server URLs or cluster names of the cluster GreenKube runs in, besides `https://kubernetes.default.svc` and `in-cluster`.
- **Periodic re-check of open deletion pull requests (H6).** The automation controller step `deletion_recheck` (every 5 minutes, 20 plans per pass) runs the collectors' full orphan check for every `pr_open` `delete_resource` plan. A resource that is in use again (a LoadBalancer that gained endpoints or a Gateway/Ingress/HTTPRoute reference, a volume bound or claimed again) gets a "do not merge" comment on its pull request (marker `<!-- greenkube:deletion-recheck -->`), the pull request is closed when the provider adapter supports it, the plan becomes `stale` (`deletion_target_in_use`) and the recommendation is retired. An unreadable cluster leaves the pull request open and is re-checked on the next pass.
- **Render inputs recorded with every plan (D7).** `validation.render_inputs` (every file the render read with its Git blob ID: Kustomization files, resources and patches of the overlay and its bases, Helm values files, repository chart files, raw manifests in scope) and `validation.render_scopes` (directories where an added file changes the render) are bound by the plan digest. They are omitted when empty, so the digests of existing plans do not change.

### Fixed
- **GitOps discovery ignored the destination cluster (delivery safety).** An Argo CD Application whose `spec.destination` is another cluster, and a Flux Kustomization or HelmRelease with `spec.kubeConfig`, bound local workloads and resources with the same namespace and name. Their candidates are now `blocked` (`destination_remote`, destination as evidence) and their inventories never resolve a resource binding, deletions included.
- **Argo CD source type assumed raw (delivery safety).** When `status.sourceType` was missing (Argo CD ComparisonError), a Kustomize overlay or a chart was bound as raw manifests and its plans failed render validation. Such a source without an explicit renderer configuration is now unresolved (`source_type_unknown`); `status.sourceTypes` is read per source of a multi-source Application, a reported `Helm` source on a Git path binds the Helm renderer and a `Plugin` source is blocked.
- **A moved branch head was accepted without re-render (D7).** Approval and the plan worker compared only the blobs the plan edits; a moved head that changed a Kustomize base or patch, a values file, `Chart.yaml` or a template the plan does not edit was accepted. A moved head is now accepted only when no render input changed (tree comparison of the planned base and the head); otherwise the plan is `stale`. Plans without recorded render inputs are `stale` on any moved head. Rollback plans watch every input of their original plan.
- **A deletion pull request was never invalidated (H6).** The worker only checked the PersistentVolume phase and the Service type once. It now runs the collectors' full orphan check (Endpoints and EndpointSlices, pods and workload templates, Gateway/Ingress/route references, owner and gateway/mesh labels; volume phase, claim, StatefulSet and snapshot dependencies) before creating the branch (`deletion_target_in_use`; an unreadable dependency is retried, never read as unused), and open deletion pull requests are re-checked periodically (see Added).
- **Commit-only `GreenKube-Plan` trailer did not link a patch delivery (automation follow-ups item 4).** The delivery verification read only the pull-request description, so the trailer linker's commit-message matches were refused; a trailer in the PR commit messages now links the request.
