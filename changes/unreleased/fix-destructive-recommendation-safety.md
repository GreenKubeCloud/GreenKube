### Added
- **Evidence for every deletion recommendation (roadmap H6 groundwork, user-reported bug).** LoadBalancer, PersistentVolume, zombie and idle-namespace recommendations say the resource *appears* unused and list the evidence (selector matches, EndpointSlice endpoints, Gateway/Ingress/route references, StatefulSet and snapshot dependencies, observed span) and the unused duration. See "Why GreenKube thinks a resource is unused" in `docs/recommendation.md`.
- **`DELETION_MIN_UNUSED_DAYS` (Helm `config.recommendations.deletionMinUnusedDays`, default `7`).** A LoadBalancer Service or PersistentVolume must look unused continuously for this long before its deletion is recommended; zombie workloads and idle namespaces need idle observations spanning it. First-seen times are stored in the new `deletion_candidates` table (migration `0063`, SQLite and PostgreSQL); the clock restarts when the resource is used again, re-created, or not observed for 48 hours.
- **Opt-out annotations.** `greenkube.io/ignore: "true"` or `greenkube.io/keep` on a Service, PersistentVolume or namespace stops deletion, zombie and off-peak recommendations for it.
- **Eligibility code `deletion_requires_review`.** Every deletion type is blocked from pull requests with an explanation and a fix (no deletion PR is automated in this release).
- **Read-only RBAC for deletion evidence:** `endpointslices`, `ingresses`, Gateway API `gateways` and routes, `cronjobs`, `volumesnapshots` and `volumesnapshotcontents`. A missing permission blocks the recommendation instead of being read as "unused".
- Recommendation event type `retired`.

### Changed
- Zombie, idle-namespace and off-peak scale-to-zero recommendations never target infrastructure namespaces (`kube-*`, `*-system`, monitoring, GitOps, ingress, storage, GreenKube...), whatever `RECOMMEND_SYSTEM_NAMESPACES` says, nor operators, controllers, webhooks or DaemonSets. Off-peak schedules also skip bare pods, Jobs, CronJobs and HPA-managed workloads. Idle namespaces require the namespace metadata (fail closed), skip `default` and namespaces younger than the minimum period, and point GitOps-managed namespaces to Git.

### Fixed
- **A LoadBalancer in use was recommended for deletion (user-reported: the Cilium Gateway API entry point of a kubeadm cluster).** The collector treated every `LoadBalancer` Service with no address in its legacy `Endpoints` object as orphaned. It now never reports selector-less Services, Services with owner references or gateway/ingress/mesh controller labels, Services with endpoints in EndpointSlices (ready or not), Services whose selector matches a pod or a workload template (scaled to zero), or Services referenced by a Gateway address, an Ingress or a Gateway API route; unreadable evidence means no recommendation.
- **PersistentVolume false positives:** `Available` volumes pre-bound to a claim not created yet, volumes of a StatefulSet scaled down, snapshot sources, `local`/`hostPath` volumes and volumes whose claim name exists again are no longer reported.
- **Existing false positives are retired on upgrade:** migration `0063` moves active `ORPHANED_LOAD_BALANCER` and `ORPHANED_PERSISTENT_VOLUME` recommendations to `stale` with a `retired` event (`deletion_evidence_required`); the ones the evidence confirms come back after the minimum unused period.
