### Fixed
- **Prometheus scrape token ignored in Helm installs (e2e).** Settings declared with an alias (`GREENKUBE_METRICS_TOKEN`, `GREENKUBE_API_KEY`) were read from the mounted secret files under their field name, which the settings model ignores: the API and the controller never saw the generated scrape token and answered `401` to the ServiceMonitors. Secret files are now keyed by the alias.
- **e2e projection-accuracy step failed every default quickstart run.** `hack/e2e/loop.sh` compared projected and measured cost even when change measurement is off (the quickstart default), so no change was recorded and the step failed with "no decided measurement". It is now recorded as `skipped` with a pointer to `values-change-measurement.yaml`.
- **`destination_remote` binding reason shown as `redacted`.** The bindings API did not list the reason of a workload whose Argo CD Application or Flux object deploys to another cluster among its safe reason codes.
- **OOM-killed workload never got its memory increase pull request.** A Deployment whose rollout is complete but whose pod crash-loops was reported as `rollout_in_progress`, which blocked every plan, including the increase-only fix that is the remedy (and made the Argo CD `Degraded` exemption unreachable). Discovery now records `rollout_pods_unavailable_only`, and the rollout gate lets an increase-only reliability plan through in that case; real rollouts (an older ReplicaSet still running, an unobserved generation) still block.
- **A CPU decrease rode along with the memory fix of a crash-looping container.** CPU and memory proposals of one container share one action, so the bundled decrease made the fix not increase-only and kept it blocked. An OOM-killed or restarted container is no longer offered a CPU decrease (its samples cover its back-off, not its load), as was already the case for memory.
- **Re-previewing an unapproved plan returned the old preview after the binding was refreshed.** Approving it then always failed with `source_changed` (seen with a crash-looping workload, whose live evidence refreshes the binding every discovery cycle). The old preview is now marked stale and a new attempt is planned.
- **HTTP 500 when planning a Flux HelmRelease whose chart leaves `metadata.namespace` to Helm.** Normalising the rendered chart lost the namespace of each document and failed with a `KeyError`; the release namespace is kept.
