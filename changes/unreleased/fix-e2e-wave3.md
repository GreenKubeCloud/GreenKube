### Fixed

- **`helm upgrade --reuse-values` from 0.3.x failed with a nil-pointer template error (F17, e2e):** Helm then keeps the 0.3.x chart's defaults, so every key added in 0.4 (`api`, `controller`, `renderer`, `sources`) is missing and `krr-cronjob.yaml` dereferenced `.Values.sources.krr`. The chart now stops before changing anything with `the chart defaults are missing` and the two commands that work (`--reset-then-reuse-values`, or `-f <your-values.yaml>`); `docs/upgrading.md` no longer suggests `--reuse-values`. Checked on Minikube: the published 0.3.1 standalone release (schema 37, data) upgrades with `--reset-then-reuse-values` to api, controller, renderer and the kept PostgreSQL StatefulSet, claim and Secret in 20 s, migrations 0038 to 0078 run once, rows and sign-in preserved.
- **Small containers never got a decrease (e2e):** the Metrics API container working set and the pod cgroup's are sampled at different instants, so a 6.7 MiB container in a 5.8 MiB pod (15% above) was taken for contradicting data and its 384Mi → 16Mi decrease was dropped. The container/pod consistency check now allows an absolute slack (4 MiB, 5 millicores) on top of the 5% tolerance; page-cache inflation (hundreds of MiB) is still bounded by the pod.
- **A LoadBalancer Service without an address projected a cloud bill (USER BUG 4 follow-up):** a pending Service (no cloud controller, an empty MetalLB pool, MetalLB < 0.13 which does not annotate its Services) was priced at `LOAD_BALANCER_COST_PER_MONTH`. It now projects no cost saving (`cost_source` `none`, detail `load_balancer_without_address`) and says why.
- **Change records linked their pull request on the in-cluster Gitea API host:** `GET /api/v2/changes` (the `/changes/{plan_id}` and `/ledger` pages) returned `http://gitea-http.gitea.svc...` while the other pull-request APIs return the provider's `webBaseUrl` origin. Change payloads now rewrite a Gitea API origin to its `webBaseUrl`.
- **Quickstart (`docs/examples/quickstart/values.yaml`, `make e2e`):** the oversized sample workloads only get decreases, which waited for the default 7 days of coverage (`minDecreaseCoverageDays: 0.001` now), and a merged change was measured by change measurement (7-day baseline, 7-day post-window) instead of the 6-minute verifier the quickstart promises (`changeMeasurement.enabled: false` now).
- **e2e harness:** `hack/e2e/install.sh` waited for the 0.3.x `deployment/<release>` (now `<release>-controller`, `-api` and `-renderer`), and `hack/e2e/cleanup.sh` now waits for the PostgreSQL volume of the deleted namespace to be removed (and removes a leftover Minikube hostpath volume), so a fresh install never inherits the previous database and its password.
- The setup page's fallback hint named `automation.providers[].allowlist` instead of `automation.repositoryAllowlist`; the PrometheusRule values comment named `collector.metricsPort` instead of `controller.metricsPort`.
