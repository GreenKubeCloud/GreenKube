### Fixed

- **The Polaris job failed on every run (G4, e2e):** `polaris audit` 10.x lists ConfigMaps, ServiceAccounts, Roles, RoleBindings, ClusterRoles and ClusterRoleBindings for its built-in checks and exits on the first forbidden list, so the init container failed before any report was pushed. The job's ClusterRole now grants `get`/`list` on them (still no Secrets, no writes), and the upload strips a trailing newline from the API key Secret (a key stored with `--from-file` made `urllib` refuse the header). Checked on Minikube: the job pushed 726 hygiene findings.
- **Orphaned LoadBalancer and PersistentVolume recommendations never got their deletion pull request (H6, e2e):** the typed action is stored inside the `patch` column, and a `delete_resource` action has no legacy patch view, so the scan's action was dropped on write and every deletion reported `action_unavailable`. The action is now stored in a patch without operations.
- **Remote (and local) Helm charts whose templates omit `metadata.namespace` could not be planned (H2, e2e):** the rendered Deployment had no namespace, so planning answered `unsupported_source` ("the exact workload target was not produced"), for example for the podinfo chart. Namespaced resources rendered without a namespace are now placed in the release namespace, as `helm install`, Argo CD and Flux do.
- **Warm-up `eligible_at` was in the past for workloads created after the install (F7, e2e):** `eligible_at` was computed as the install's first sample plus `minSamples` steps, so a Deployment created a day after the install, with 1 of 6 samples, reported "warming up" with an `eligible_at` a day earlier and the fix text "Enough data should now be available". While samples are missing, `eligible_at` is now at least the evidence end plus the missing samples (one per step).
