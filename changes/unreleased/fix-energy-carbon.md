### Added
- **Embodied emissions provenance (NRG-01):** pod, container and node idle rows carry `embodied_source` (`boavizta`, `configured`, `fallback_per_vcpu`, `fallback_default`; migration 0180). Rows of a fallback are flagged estimated with an "Embodied emissions estimated" reason, and projections list `embodied_sources` in their assumptions.
- **Operator embodied value:** the node annotation `greenkube.io/embodied-kg`, then `EMBODIED_KG_BY_INSTANCE_TYPE` (Helm `config.boavizta.embodiedKgByInstanceType`, a map of instance type to kg), set the whole-node embodied emissions of on-prem hardware and take precedence over Boavizta.
- **Capacity-proportional embodied fallback:** `DEFAULT_EMBODIED_KG_PER_VCPU` (12 kg per vCPU, the Boavizta m5 family ratio) and `DEFAULT_EMBODIED_KG_PER_GIB` (0), Helm `config.boavizta.embodiedKgPerVcpu` and `config.boavizta.embodiedKgPerGib`. `DEFAULT_EMBODIED_EMISSIONS_KG` now applies only when the node capacity is unknown.

- **Shared host detection (NRG-15):** nodes with the same `bootID` (or `kind://`, `k3d://` provider IDs) are treated as one host; each of N nodes gets 1/N of the host idle power, memory power and embodied emissions, rows carry a "Shared host" estimation reason and `greenkube_shared_host_groups` counts the groups. On a three-node kind cluster the modelled baseline drops by about two thirds. Opt out with `config.power.sharedHostDetection: false` (`SHARED_HOST_DETECTION`). `greenkube recompute` and projections do not apply it yet.
- **GPU nodes without DCGM (NRG-13):** GPUs declared in the node capacity (`nvidia.com/gpu`, `amd.com/gpu`, `gpu.intel.com/*`) are detected; when DCGM has no sample, each GPU a pod requests (container requests or limits) is charged to that pod at `idle + util × (TDP − idle)` of its TDP profile (`nvidia.com/gpu.product` label) with an assumed utilisation of 50 % (Helm `config.power.gpuAssumedUtilizationPct`, `GPU_ASSUMED_UTILIZATION_PCT`); the other GPUs are counted at the idle floor on the node's idle row. Rows carry "GPU power estimated from TDP". GPUs of an unknown model are flagged "GPU power not measured" and counted by `greenkube_gpu_nodes_unmeasured`. Pod snapshots store the GPU request of containers that request GPUs; other pods keep their snapshot hash. Pod, container and idle rows carry `gpu_source` (`dcgm`, `gpu_tdp_estimate`, `unmeasured`, NULL without GPUs; migration 0182).
- **CPU used outside pods (NRG-12):** node utilisation now takes the kubelet root cgroup (`container_cpu_usage_seconds_total{id="/"}`) when it exceeds the pods' sum, so kubelet, container runtime and kernel CPU count in dynamic node power; that system share goes to the node's `__idle__` row, pods keep their own share. Without the series nothing changes.

### Changed
- **Impact Model 4.0.0:** embodied emissions change for every node. Rows stored before keep the flat 100 kg per node with `embodied_source` NULL; run `greenkube recompute --since <raw retention>` to re-allocate raw rows. Hourly aggregates keep the old values.

### Fixed
- **DCGM outages no longer drop GPU power (NRG-13):** once the collector has seen DCGM series, a DCGM query error fails the collection window, which is retried, instead of storing it without GPU power. On a cluster where DCGM never returned series an error stays a warning.
- **SQLite pod-row readers return `embodied_source` and `gpu_source`:** they selected an explicit column list without them, so rows read back and rewritten on SQLite (re-allocation) would lose `gpu_source`; PostgreSQL readers already returned every column.
- **Boavizta values are used (NRG-01):** the response model now matches the Boavizta API v1 (`impacts.gwp.embedded` and `use` are objects); before, every lookup failed and every node got the flat 100 kg fallback, unflagged. The lookup asks for `verbose=false` and no `duration`, so the value is the lifetime embedded GWP (24 kg for `aws/m5.large`). A failed lookup is stored in `instance_carbon_profiles` with its error and retried at most every 24 hours instead of on every collection cycle; on-prem providers (`unknown`, `kind`, `k3s`, ...) are never looked up.
- **Live intensity for the default zone (NRG-03):** the hourly carbon intensity job fetches the zones the rows are computed for, with the same zone resolution, plus `DEFAULT_ZONE`; on-prem, kind, k3s and kubeadm clusters without zone labels now get live intensity with a token. The job no longer returns before the 24 h recompute when no zone maps or no node is listed, and `greenkube_intensity_zones{zone,status}` reports the outcome per zone (`fetched`, `empty`, `failed`).
- **Bundled zone intensity defaults repaired (NRG-04):** the table was a one-day reading (23/11/2025) with 251 of 349 zones empty and five column-shifted rows (ES, SE, NO, DK, AU), so 19 of the 51 zones cloud regions map to (NL, SE, IT, ES, CH, AT, ...) fell back to 500 gCO2e/kWh. It now holds the 2024 annual life-cycle mean of each country from Ember's yearly electricity data (186 zones, with year, source and factor type per row, validated at load), regenerated by `scripts/generate_zone_intensity_defaults.py`. A sub-zone without a value of its own uses its country's (`intensity_source=country_default`). Every mapped cloud region and Wattnet zone now has a default. `GET /api/v1/config` reports the year as `intensity_defaults_year`. Rows already stored keep the intensity they were computed with.
- **One node power model for projections and rows (NRG-05):** the projector resolved the power of nodes without a bundled instance profile with 1 W idle and 10 W max per core, while collected rows use the provider's CCF per-vCPU coefficients (0.6 to 0.8 W idle, 2.8 to 4.3 W max). Both now call `resolve_node_power_profile`. Projected CO2e of open recommendations on such nodes drops by up to about 40 % (the idle share) at the next scan, which re-projects them with Impact Model 4.0.0.
- **Node snapshot versions no longer flip every cycle (NRG-07):** the collection no longer writes node snapshots; `embodied_emissions_kg` in `node_snapshots_scd` holds only the operator annotation. Migration 0181 clears the derived values stored there and collapses the identical consecutive versions they created. `greenkube recompute` resolves embodied emissions from the stored Boavizta profiles like the collection, so a recompute no longer zeroes embodied CO2e.
