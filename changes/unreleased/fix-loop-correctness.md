### Added
- **`kind` filter on `GET /api/v2/recommendations` (E4):** finding kinds (the v1 types such as `RIGHTSIZING_MEMORY`), case-insensitive, repeatable or comma-separated; an unknown kind returns `422`. The parameter was previously accepted and ignored.
- **Planner reason in plan preview errors (D12):** a failed `POST /automation/plans` or `POST /automation/plans/{id}/rollback-preview` returns, next to the stable `code` and `detail`, the planner's own `reason` for targeting, binding, source, render and rollback errors (for example `recommendations do not share one persisted action`), redacted like preview warnings (URL credentials, query strings, secret assignments, provider tokens) and bounded to 300 characters. Provider, policy and chart-mapping errors keep their structured fields only.
- **`restarts_in_window` reliability signal (E9):** container restarts over the lookback (`increase(kube_pod_container_status_restarts_total)`, kube-state-metrics), 0 when kube-state-metrics reports none.

### Changed
- **Revision hysteresis (E7):** a request proposal that moved by at most 5% from the stored one (same kind, same observed current request, same direction) keeps the stored advice, so working-set jitter no longer creates a revision on every scan (the wave-4 e2e saw 22 memory revisions in 20 minutes).
- Rollback previews of container resources restore the baseline in canonical units (`512Mi` instead of `536870912`), byte for byte.

### Fixed
- **OOM-killed containers get a memory increase (E9):** when the spike is shorter than the scrape, the observed maximum stays small and no increase was proposed despite OOM kills. An OOM kill now proves the container reached its memory limit (its request without a limit): the increase is at least that value × 1.1, bounded by `RIGHTSIZING_MAX_INCREASE_FACTOR` × the request (basis `oom_limit`), and the memory limit is raised with it.
- **No memory decrease after OOM kills or restarts (E9):** a container OOM-killed or restarted within the lookback is never offered a memory decrease.
- **CPU+memory pairs under an open plan (E7, H1):** refreshing a frozen recommendation whose advice was unchanged rewrote its copy of the shared workload action with its sibling's newer value, so the members of an open plan diverged and the plan failed with `requires_container_target` / `source_changed` until it was cancelled. A frozen record now only has its liveness refreshed, and the refreshing write is conditional on no plan being open (SQLite and PostgreSQL).
- **Canonical Kubernetes quantities in every planner (H1):** memory requests and limits are written in binary units (`23Mi`, `1Gi`) to raw manifests, Kustomize patches, Helm values and the Flux post-renderer, never as a raw byte count (`memory: '24114500'`). Native memory decreases are whole mebibytes, and a proposal from another source that is not is rounded up to the next mebibyte when written.
- The `action_unavailable` blocker of a deletion (orphaned LoadBalancer or PersistentVolume) talks about the deletion, not container resources.
- Flaky tests: module-level wall-clock constants (`NOW`, `END`, `T0`, `BASE`...) are re-read at test time, so long full-suite runs no longer age bindings past their freshness window (`test_plan_runtime_resource_bindings`, `test_gitops_router`, `test_recommendation_decisioning` and others).
