### Added
- **Pricing currency in `GET /api/v1/config` (B3, K1).** The response adds `currency` (`impact.pricing.currency`). The UI reads it once after sign-in and formats every amount with it (costs, savings, ledger totals, chart legends); a value that carries its own currency keeps it.
- **Realization factor in the UI (B6, C2, principle 3).** The Overview, the Ledger, the Recommendations savings tab and each change measurement show the realization factor of measured savings and the billed saving it implies, labeled as an expectation. Explicit `measured_allocated_*`, `realized_billed_*` and `realization_factor` fields are used when the server sends them, otherwise `realized_to_date`, `run_rate_annual` and `realization.realization_factor`.
- **Read-only hints (F16, K11).** A viewer sees a "Read-only access" note on the Recommendations and Automation pages instead of actions that end in `403`.
- **Analyzer tuning keys documented (docs/configuration.md):** `rightsizingCpuThreshold`, `rightsizingMemoryThreshold`, `rightsizingHeadroom`, `minCpuMillicores`, `minMemoryBytes`, `applyTolerance`, the zombie, autoscaling, off-peak, idle-namespace, carbon-aware and node-utilization thresholds, `recommendSystemNamespaces`, `storageCostPerGibMonth`, `loadBalancerCostPerMonth`, plus `config.logFormat`, `config.defaults.*`, `config.prometheus.verifyCerts`, `config.prometheus.nodeInstanceLabel` and `config.opencost.verifyCerts`.

### Changed
- **Savings vocabulary (principle 3).** Measured savings read **Measured allocated savings**, **Measured allocated run rate** and **Allocated CO₂e** instead of "Realized savings" and "CO₂e avoided"; "Realized" is reserved for billed savings (`realized_billed`). Measurement outcomes and change states `realized` / `not_realized` read **Saving measured** / **No saving measured**.
- **Pull requests tab of `/recommendations` (K4).** It is now a link to the changes board (with the open pull-request count) instead of a second list.
- **Auto-approval blockers (H1, F5).** The plan preview names `increase_without_native_evidence`, `increase_requires_approval`, `deletion_requires_review` and `auto_approve_failed` in words.
- **`action_unavailable` fix text (E9, H1).** It says the action is rebuilt once the request change (increase or decrease) is known, not only a decrease.
- **README.** "What works today" and "On the roadmap" follow the unreleased changelog: always-on automation with `automation.policy.pauseDelivery` as the switch, consensus, the new sources, increases, deletions, remote charts, manual mode, ledger v2 and SSO are listed as delivered.

### Fixed
- **Time to the first pull request was overstated (F7, E9).** The setup checklist (`evidence` check), the installation guide, the README quick start and the Helm install notes promised pull-request-ready evidence after about 3 hours, but request decreases need `config.recommendations.minDecreaseCoverageDays` (7 days). The checklist now reports two estimates: increases and the other sources after `minSamples` samples, decreases after the decrease coverage from the first sample.
- **Hard-coded `$` (B3).** `formatCost`, the ledger totals and the cost chart legend always showed dollars whatever `impact.pricing.currency` said.
- **Viewer saw mutating actions (F16).** **Open PR**, **Ignore**, **Restore**, **Rescan**, plan cancel, re-plan and rollback, **Refresh discovery**, **Resolve binding**, **Mark as applied** and the footprint cache refresh are shown only with the `write` scope (a viewer gets a read-only reload), and plan approval only with the `approve` scope (or when the plan does not answer `may_approve: false`).
- **Stale documentation (F11).** References to the removed standalone and production profiles, to `config.api.enabled` as a requirement of the KRR and Polaris jobs, to `automation.workerMetricsPort` and to the old `deploy/greenkube` log command are gone; the split API server table of `docs/configuration.md` is whole again.
