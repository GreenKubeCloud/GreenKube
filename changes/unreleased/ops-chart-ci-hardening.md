### Added

- **Ingress and Gateway API HTTPRoute (N6):** optional `ingress.*` (class, hosts, TLS, annotations, labels) and `httpRoute.*` (parentRefs, hostnames, scheme, annotations, labels) templates route the hosts to the api Service under `config.rootPath` (or `/`). `GREENKUBE_EXTERNAL_URL` is now `config.externalUrl`, else the first Ingress host (`https` when a TLS entry covers it), else the first HTTPRoute hostname (`httpRoute.scheme`), else empty; a wildcard host builds no URL. Values validated by `values.schema.json`; `docs/configuration.md#exposure-ingress-httproute`.
- **Loop health alerts (N7):** the PrometheusRule gains the `greenkube.loop` group, rendered with the controller loop alerts: `GreenKubeCollectionLagging` (leader `greenkube_collection_watermark_lag_seconds`), `GreenKubeRecommendationScanFailing` and `GreenKubeRecommendationScanStale` (`greenkube_optimization_runs_total`, `greenkube_last_successful_optimization_run_timestamp_seconds`), `GreenKubeRecommendationSourceFailing` (`greenkube_optimization_analyzer_failures_total`), `GreenKubeMeasurementStalled` (`recommendation-lifecycle` loop heartbeat) and the critical `GreenKubeLedgerChainVerificationFailed` (`greenkube_ledger_chain_verification_failures_total`). Thresholds in `monitoring.prometheusRule.thresholds.{collectionLagSeconds,recommendationScanStaleSeconds,measurementStaleSeconds}`. The rules are unit-tested with `promtool` (`helm-chart/tests/promtool/`, `.github/scripts/promtool-check.sh`, run in CI).
- **Pod Security `restricted` CI check (N5):** `.github/scripts/psa-restricted-check.sh` sends several renders of the chart through `kubectl apply --dry-run=server` into a namespace that enforces `restricted` and fails on any "would violate PodSecurity" warning; the new `psa-restricted` CI job runs it on kind. A helm-unittest suite checks the security context of every pod.
- **Nightly end-to-end loop (O1):** `.github/workflows/e2e-nightly.yml` runs `make e2e` on a fresh Minikube every night, on demand and on pull requests touching delivery or verification; `.github/e2e/bootstrap-minikube.sh` installs pinned metrics-server, kube-prometheus-stack, Argo CD, Flux and Gitea (with an API token). The evidence, pod logs and events are uploaded as the `e2e-evidence` artifact and the steps are listed in the job summary.
- **Release supply chain (O6):** release images are signed with cosign (keyless), carry a syft SPDX SBOM as a signed attestation, BuildKit provenance and SBOM, and SLSA build provenance (GitHub artifact attestations); the chart package gets provenance and a Sigstore bundle. The SBOM, chart and bundle are attached to the GitHub Release. `SECURITY.md` explains how to verify them.
- **`make test-pg` (O8):** runs the suite against a disposable PostgreSQL from `docker-compose.test.yml` (`TEST_PG_PORT`, `TESTS`, `PYTEST_ARGS`, `TEST_PG_KEEP`). CI and the release gate now fail when a PostgreSQL test is skipped for a missing `GREENKUBE_TEST_POSTGRES_DSN` (`.github/scripts/check-postgres-ran.sh`).
- **Community files (L10):** `SECURITY.md` (private reporting, response times, scope, release verification), `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1), issue forms (bug report, feature request) and a pull request template.
- `actionlint` CI job for the workflows.

### Changed

- **Every GitHub Action is pinned by commit SHA (O6)** with its version in a comment; Dependabot keeps the pins current.
- **Grafana dashboard and UI metadata (L11):** the dashboard is titled "GreenKube — Savings & Footprint" with a loop-oriented description and tags (uid `greenkube-fingreenops` kept for existing imports); `frontend/src/app.html` drops "FinGreenOps platform" for the loop positioning and adds `application-name`, `theme-color` and `robots: noindex` metadata.
- `docker-compose.test.yml` publishes PostgreSQL on `${GREENKUBE_TEST_PG_PORT:-5432}`.

### Fixed

- **The bundled PostgreSQL runs without a root init container (N5):** the `init-pgrun-perms` init container ran as UID 0 with `CHOWN`/`FOWNER`, so the chart could not install in a namespace enforcing Pod Security `restricted`. `fsGroup: 70` already makes the socket directory writable and the image entrypoint ignores its own failed `chmod`; every pod the chart renders by default is now `restricted`-compliant. The optional `renderer.egressFirewall` init container (root, `NET_ADMIN`) is documented as the one exception.
- `docker-compose.test.yml` mounted its tmpfs on `/var/lib/postgresql/data`, which the PostgreSQL 18 images no longer have, so the container failed to start on recent Docker versions; it now mounts `/var/lib/postgresql`.
