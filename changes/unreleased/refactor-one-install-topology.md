### Added

- **Always-on automation with capability activation (F12):** the controller's `automation-readiness` loop reconciles every minute: it infers a Git provider for each repository host referenced by discovered Argo CD/Flux sources (`github.com`, `gitlab.com`, or a self-hosted GitLab/Gitea identified by probing `/api/v4/version` and `/api/v1/version`), gives it the default credentials Secret `greenkube-git-credentials` (key `token`), enables it only while that Secret is mounted, expands the `@discovered` allowlist and asks discovery to re-resolve bindings. Creating the Secret activates delivery within about a minute, deleting it makes delivery dormant again, with no upgrade and no restart. Per-repository and global capability states are stored in the new `automation_capabilities` table (migration 0071) and exported as `greenkube_capability_active{capability}`; the plan executor runs only while delivery is active, the webhook outbox and PR polling only while tracking is.
- **`automation.policy.pauseDelivery` (F12):** the only off switch. Plan approval returns `409 delivery_paused`, queued operations wait, and discovery, previews, PR tracking and measurement keep running.
- **Guided setup checklist API (F1):** `GET /api/v1/setup/status` returns `{complete, checks[{id, category, title, status, reason, fix{text, snippet, ui_action}, docs_url}], capabilities{discovery, delivery, sync_tracking, measurement}}` over data sources, recommendation sources, GitOps controllers, repositories, Git credentials, the renderer, the plan executor and the evidence warm-up (with an ETA).
- **Allowlist suggestions and provider inference (F2):** `GET /api/v1/automation/repositories/suggestions` lists discovered repositories with their inferred provider type, API URL and allowlist state; `POST /api/v1/automation/repositories/allowlist` (`admin` scope) allows discovered repositories in the database (table `automation_repository_allowlist`) and returns the equivalent `automation.repositoryAllowlist` values snippet.
- **Renderer egress canary (F6):** the renderer checks at startup and daily that its egress-deny NetworkPolicy is enforced (a TCP connection to the Kubernetes API Service address must fail) and serves the result on `/status`; the setup checklist reports `renderer_egress_unenforced` with the init-container firewall fix. The renderer listens on `renderer.servicePort` (`RENDERER_PORT`).
- **`greenkube db copy` (F17):** copies a 0.3.x SQLite database into PostgreSQL. The source file is never written (a working copy is migrated to the current schema), tables are copied parents first with `ON CONFLICT DO NOTHING` (reruns are idempotent), values are converted to the PostgreSQL column types and identity sequences are advanced. Metric history only with `--include-metrics`; `--dry-run` counts rows.
- **`values.schema.json` (N2):** wrong types and out-of-range values (intervals, ports, replicas, enums such as `missingEvidence`, `secureCookie`, `apiAuthMode`, provider types, image digests) are rejected before rendering; most template `fail` guards are gone.
- **Upgrade checks without a cluster (F17):** `tests/helm/test_helm_topology.py` renders the 0.3.1 chart (git tag) and the current chart with the same values and checks that the PostgreSQL StatefulSet, claim, Service, Secret, Lease and selectors survive, that deprecated values map, and that a SQLite release fails with the exact migration commands.
- **`docs/upgrading.md`:** the 0.3.x upgrade path, the deprecated-value mapping and the SQLite copy Job.

### Changed

- **One install topology (F11):** `helm install` with no values renders exactly `<release>-api`, `<release>-controller`, `<release>-renderer` and the bundled PostgreSQL, plus Services, RBAC, NetworkPolicies and the always-rendered controller Lease. One `components.yaml` template renders the api, controller and optional worker (`worker.replicas`, default 0) from a shared container spec; the `wait-for-postgres` init container stays. Default requests total about 325m CPU / 600 MiB (api 100m/128Mi, controller 100m/256Mi, renderer 25m/96Mi, PostgreSQL 100m/128Mi). High availability is `api.replicas: 2` and `controller.replicas: 2`.
- **Migrations at controller startup (F11):** only the controller migrates (`DB_RUN_MIGRATIONS=true`, PostgreSQL advisory lock); the API and workers skip migrations and `/api/v1/health` answers `503 migrating` until every shipped migration is applied (cached once current). The API no longer writes provider rows at startup. The controller's readiness probe is `/readyz` of its loop registry, with a startup probe budget for long migrations.
- **Automation is always on (F12):** `automation.enabled` and `automation.mode` are removed (mapped for one minor release, see below); the Argo CD/Flux discovery RBAC is always rendered read-only; the default credentials Secret is mounted as an optional projected volume into the api, controller and worker; `automation.repositoryAllowlist` defaults to `["@discovered"]` and is used by providers without their own allowlist. The eligibility blocker `automation_disabled` now means delivery is paused. `GET /api/v1/automation/status` reports `mode` `controller` or `paused` and `delivery_paused`.
- **Knob reduction (N3):** one `config.recommendations.minSamples` sets the recommendation, plan-policy and verification sample gates; sources are grouped under `sources.*` (`sources.priority` replaces `config.recommendations.sourcePriority`); `rendererSandbox.*` becomes `renderer.*` and the renderer is always deployed with 25m/96Mi requests (F6); `collector.metricsPort` becomes `controller.metricsPort`; the ConfigMap is a regular release resource named `<release>-config`; `missingEvidence` defaults to `fail`.
- **Installation guide rewritten as one path (F18):** `helm install`, sign in, optionally one Secret for Git, done; external PostgreSQL, Ingress/TLS, HA and SSO are additive sections. The README quick start, configuration reference, automation guide, architecture and CLI reference follow.

### Removed

- The `profile` (standalone/production), `replicaCount`, `production.*`, `automation.enabled`, `automation.mode`, `automation.workerMetricsPort`, `rendererSandbox.*`, `collector.*`, `resources`, `apiResources` and SQLite values (`config.db.type`, `config.db.path`, `config.persistence`) — accepted and mapped for one minor release with a **DEPRECATED VALUES** list in the install notes (F17); `values-production.yaml`; the standalone two-container pod (`deployment.yaml`), `production-deployments.yaml`, the migration Job hook, the database credential-check hook and the pre-install ServiceMonitor CRD check hook. The only remaining hooks are the `helm test` pod and the credentials bootstrap (N1).

### Fixed

- **BUG-61:** the production profile enabled automation with no providers and showed a permanent "not ready"; automation now reports each capability with its reason and the fix in the setup checklist.
- **SQLite releases no longer lose their data on upgrade (F17):** a `config.db.type=sqlite` release fails before Helm changes anything, with the exact `helm upgrade`, `greenkube db copy` and scale commands; the former claim is kept (`helm.sh/resource-policy: keep`) while `config.persistence.enabled` is set.
