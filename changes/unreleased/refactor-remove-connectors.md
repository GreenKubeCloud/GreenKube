### Changed
- **Consensus has one policy: GreenKube's measured value decides the size.** In a container request or limit group the consolidated value is the native analyzer's; VPA, Goldilocks, KRR and pushed signals never move it. They move the confidence: two or more independent sources that agree (agreement of at least 0.8) raise it by 10%, a contested consensus (agreement below 0.5, or opposite directions) lowers it by 20% (`consensus_agreement` confidence factor 1.1 or 0.8). A source alone still never creates a recommendation (A.5). The consensus block records `policy: "native"`; non-numeric proposals prefer the native one, then the most supported. A decrease from a VPA of unknown maturity is always set aside (`maturity_unknown`). A supporting external source that is incomplete no longer holds back the native value; its last known vote is still listed (`consensus.last_known`). Existing records are rebuilt by the next scan, which may change their proposed value (a new revision).
- `docs/sources/krr.md` is a ready-made example: a CronJob (with its read-only RBAC) that runs KRR and posts the report to `POST /api/v1/sources/krr/reports`, the push contract of that endpoint, and the CI variant.

### Removed
- **Connectors Kubecost, GKE recommender, Azure Advisor and Polaris**, their docs (`docs/sources/kubecost.md`, `gke.md`, `azure-advisor.md`, `polaris.md`), tests and fixtures, and the `POST /api/v1/sources/polaris/reports` route (now `404` for every key, a leftover CronJob's `signals:report` key included). Their `SOURCES_CONFIG` / `sources.settings` entries are accepted and ignored for one release, with one warning at start. Push their advice to `POST /api/v1/signals` instead. The separate `replay` module is gone: the inbox source base lives in `greenkube.signals.connectors.inbox` and the `push` source in `greenkube.signals.connectors.push`.
- **Consensus policies `safest`, `median`, `weighted` and `priority`**, with `RECOMMENDATION_CONSENSUS_POLICY` and `RECOMMENDATION_SOURCE_PRIORITY` (Helm `config.recommendations.consensusPolicy`, `sources.priority`, `config.recommendations.sourcePriority`). The settings are accepted and ignored for one release, with one warning at start; the Helm values render nothing and are listed under DEPRECATED VALUES; the values schema marks them deprecated.
- **The chart's KRR and Polaris CronJobs** (`sources.krr.job.*`, `sources.polaris.job.*`, their ServiceAccounts, ClusterRoles and NetworkPolicy rules). The values are ignored with a NOTES warning. KRR stays a source: run it yourself (see `docs/sources/krr.md`).
- Migration `0310` retires the active recommendations whose chosen source was a removed connector (`stale`, event reason `type_removed`); recommendations in a pull request, measured or in the ledger are untouched, and no table is dropped.
- The unused direct dependency `anyio` (still installed through `httpx` and Starlette; no GreenKube code imports it).
