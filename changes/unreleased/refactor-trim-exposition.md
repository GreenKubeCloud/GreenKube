### Added
- **Operations dashboard** `dashboards/greenkube-operations.json` (**GreenKube Operations**, ready for Grafana.com as the new revision of dashboard 25377: `${DS_PROMETHEUS}` input, no fixed uid, no Grafana plugin; import and publishing steps in `dashboards/README.md`): an About panel linking docs.greenkube.cloud, Namespace and Cluster variables; collection data age, watermark lag, coverage, abandoned and degraded windows; controller leader, loop failures and freshness; recommendation scans and source failures; measurement loop age, ledger chain and reconciliation status, projection backlog and ledger errors; net savings by method from the ledger counters; automation backlog. Savings panels deduplicate the counters across API replicas (`max` per series before `sum`), and panels reading controller series, which have no `cluster` label, are titled *(all clusters)*. A test checks that every queried family is registered on the API registry or the control-loop registry.

### Changed
- The Footprint page no longer points to a Grafana dashboard: per-namespace and per-pod detail is in the Report section and its CSV and JSON exports.
- The API `ServiceMonitor` relabels only `exported_cluster` (and still defaults an empty `cluster` to `default`); the `exported_namespace`, `exported_pod` and `exported_region` relabelings matched no series any more.

### Removed
- **Breaking: the sustainability score** (audit API-06: no defined method; three of its seven dimensions were constants). `src/greenkube/core/sustainability_score.py`, `docs/sustainability-score.md` and the Prometheus series `greenkube_sustainability_score` and `greenkube_sustainability_dimension_score` are removed. It had no HTTP API route, UI page or stored data, so no route, setting, Helm value or table is affected.
- **Breaking: the large Grafana dashboard** `dashboards/greenkube-grafana.json` (uid `greenkube-fingreenops`, Grafana.com dashboard 25377), its generator `scripts/build_grafana_dashboard.py` and its screenshots. Import `dashboards/greenkube-operations.json` instead.
- **Breaking: footprint, recommendation and dashboard series on `/prometheus/metrics`.** The API exports collection freshness (`greenkube_last_collection_timestamp_seconds`, `greenkube_metrics_total`) and the ledger savings counters (`greenkube_{co2e,cost}_savings_{attributed,reversed}_*_total`, `greenkube_savings_measured_vs_projected_ratio`) only, next to the control-loop families. Removed: every `greenkube_pod_*`, `greenkube_namespace_*` and `greenkube_node_*` family, the cluster footprint and idle-share totals, `greenkube_pue`, `greenkube_grid_intensity_gco2_kwh`, `greenkube_carbon_intensity_score`, `greenkube_carbon_intensity_zone`, `greenkube_zone_grid_intensity_gco2_kwh`, `greenkube_estimated_metrics_ratio`, the `greenkube_dashboard_summary_*` and `greenkube_dashboard_savings_*` windows, the savings run-rate and legacy `*_saved_*_total` gauges and the recommendation gauges (`greenkube_recommendations_total`, `greenkube_recommendations_implemented_total`, `greenkube_recommendations_savings_*`, `greenkube_namespace_recommendation_savings_*`, `greenkube_top_recommendations`). On a 40-pod, 5-namespace, 3-node test fixture the API registry drops from 75 families and 3,066 series (680 with a `pod` label, 2,321 with a `namespace` label) to 7 families and 27 series; the whole endpoint from 140 families and 3,202 series to 72 and 163. A scrape no longer reads nodes, recommendations, applied records, dashboard summaries or per-window ledger breakdowns, and the controller no longer fills gauges nobody scraped. The chart PrometheusRule and its promtool tests read none of the removed series. Footprint data stays in the Footprint pages and their export routes. Replacements per series: `docs/upgrading.md`.
