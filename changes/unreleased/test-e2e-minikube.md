### Added
- **End-to-end loop harness (O1, F9):** `make e2e` builds the image from the checkout inside Minikube, installs GreenKube with demo-accelerated values, creates a sample repository on Gitea, registers it with Argo CD and Flux, and drives a sample workload through collection, recommendation, plan preview, digest approval, pull request, merge (Gitea API), GitOps sync, sync confirmation, apply detection and measurement, recording the evidence of every step. The run fails unless the measurement verdict is `verified`/`passed` (`E2E_ALLOW_REGRESSION=1` records other verdicts without failing). The scripts in `hack/e2e/` are idempotent; with `E2E_FRESH=0` a run resumes from the workload's open or merged GreenKube pull request, and the sync check accepts a later commit that contains the merge. `make e2e-status` and `make e2e-clean` inspect and remove the environment. `tests/e2e/test_live_loop.py` wraps the run (skipped unless `GREENKUBE_E2E=1`).
- **Harness safety (O1, F9):** every script that changes the cluster stops unless kubectl points at `E2E_KUBE_CONTEXT` (default `minikube`). The harness labels what it creates with `greenkube.io/e2e=true` (and marks the Gitea repository's description), refuses to install over or update objects without that marker, and deletes only marked objects, so `make e2e` cannot remove a real GreenKube installation and its database (`E2E_ADOPT=1` takes over unmarked objects explicitly). The Gitea token has no default path and reaches `curl` and `kubectl` on stdin, not on their command lines. `tests/e2e/test_harness_safety.py` checks these rules with stub CLIs.
- **`make quickstart` (F9):** installs GreenKube with the demo values next to the sample app without running the loop or deleting anything, so the first pull request can be opened from the UI.
- **Quickstart assets (F9):** `docs/examples/quickstart/` holds demo-accelerated Helm values (`RECOMMENDATION_MIN_SAMPLES=6`, 30-second `PROMETHEUS_QUERY_RANGE_STEP`, 6-minute measurement window), a sample GitOps repository with deliberately oversized workloads (raw YAML for Argo CD, Kustomize for Flux) and the Argo CD Application and Flux objects. The guide `docs/get-started/first-pr.md` walks through the loop.

### Fixed
- **Helm: the chart installs again.** The controller metrics port was named `controller-metrics` (18 characters). Kubernetes rejects port names longer than 15 characters, so every install and upgrade failed. It is now `ctrl-metrics` on the container, the `<release>-controller-metrics` Service and the controller ServiceMonitor (A12).
